## 2. 路线演化史（E1-E10，每步都有数字背书）

### 2.1 前史：M2F 路线放弃
两轮设计剖析（2026-08-17）实证砍掉了 graph / reference / NMS：graph 前提不存在（实例不重叠，协议层重复已被吃掉）；reference A/B -0.0014；手写解码 +0.063 零训练；depth 逐图 min-max 毁最强特征；30 分差距是配方不是模块。用户决定不走 M2F，问 U-Net+GNN 是否可行。

### 2.2 E1-E5：路线验证（4 天零烧卡，仅 35.7 分钟训练）
- **E1 身份信号**：depth+spatial pair AUC 0.991，外观直方图无贡献（0.584）；never-merge 平凡基线 0.9916——**合并方向天然无利可图**。
- **E2 评分模拟**：完美 mask 下 segm AP 饱和 0.9901（评分不是死因）；错误合并 0.356 < 不合并 0.408——**错合并是负收益**。
- **E3 小 U-Net**（resnet18 4ch，mIoU 0.945）：segm AP **0.0287 FAIL**。死因：91% 零件在并集 mask 里粘连（864 CC vs 9494 实例）——语义解决不了实例身份。
- **E4 深度 watershed**：0.3125 灰色；粘连 91%→8.2%；RGB 梯度 0.0260（信号全在深度）；**GT 语义天花板 0.4933**（AP75 0.28——刀口精度封顶）；GT 种子数反而 0.1798（**种子放置难于数量**）。
- **E5 判决**：U-Net+**GNN** 死刑（合并无输入、分裂靠深度不靠图）。幸存路线："**深度优先小模型实例分裂**"。

### 2.3 E6-E9：从 0.48 到 0.73
- **E6 双头（sem+center heatmap）**：1566 上 0.4797 ≥0.42 PASS，破 E4 的 GT 语义上限；机制：heatmap 种子密度 3.7× 提供覆盖，merge 吸收多余；oracle 0.5558 → 种子还有 +0.076。
- **E7 三头（+boundary）**：0.4583 灰。学到：轮廓全局可学（AUC 0.987）但**接触缝学不出**（缝对两邻件都像内部）；第三头重训伤种子头——小模型多任务不免费。
- **E8 放大到 32254**：0.4815，与 1566 持平——**数据 ×20 没换来指标**，heatmap 头没从数据学到东西；oracle 0.7952 → **种子放置占掉几乎全部瓶颈**（种子 median 46px、772 markers/img）。
- **E9 CenterNet 种子头**：stride-4 热图 + 尺寸自适应 σ=clamp(√A/12,2,8)（13 桶 49×49 核）+ penalty-reduced focal（α=2/β=4）+ offset L1 + 3×3 max-pool 峰 NMS。**0.7254**，种子 median 2.35px、<8px 96.3%、56.2 vs 55.5 markers——FINAL=oracle 98.6%，**种子问题宣告解决**。代价：oracle 从 0.7952 掉到 0.7359（第三头挤占语义容量）。

### 2.4 E10 语义容量恢复（当前）
decoder 加宽 (256..16)→(384..24)（3.15→5.61M）+ 语义头 145 参数单卷积改 3 层块 + 语义 loss ×2。总参 16.851M。20ep（~21.5min/ep），best mIoU 0.9984（ep18）。

## 3. 当前架构（E10，代码在 exp09/exp10）

### 3.1 训练
```
输入 1024×1024, 4ch = RGB + 全局标定深度（不是逐图 min-max！）
        ResNet18 encoder (11.18M, ImageNet init)
        UNet decoder (384,192,96,48,24) (5.61M)
    ┌────────┼────────┐
  语义头     种子头      偏移头
  3层块     共享主干     2ch
  (8K)     stride-4 热图
```
- 损失：语义 BCE+Dice（权重 ×2）+ 中心 penalty-reduced focal + 偏移 L1。
- 入口：`experiments/ugnn/exp10_semantic_capacity/train_capacity.py`（从 exp09 的 train_centernet.py 迭代而来）；16 workers + prefetch 4；systemd-run 上限启动（MemoryMax=48G 实测贴顶但稳定，大头是可回收页缓存）。
- 评测入口：`experiments/ugnn/exp09_cententer_seeds/eval_centernet.py`——**笔误警告：正确目录名是 `exp09_centernet_seeds`**。`--arch e9|e10` 选架构（默认 e9），`--profile fast|full`（默认 full）。

### 3.2 推理数据流（FINAL config）
```
前向(GPU ~8ms) → sem mask + 热图 + 偏移
  → 峰 NMS + (cell+offset)×4 → 亚像素种子（median 2.30px）
  → 种子光栅化为 markers
  → watershed：elevation = sobel(深度) 梯度模（离线 rank 缓存）
  → 小区域 merge → 面积打分 top100 → 列游程直出 COCO RLE
```
- 后处理 `exp09_centernet_seeds/postproc_fast.py`：numba 桶队列 watershed（精确复刻 skimage 弹出序）+ elevation rank 预计算缓存 + bbox 裁剪 RLE。单进程 69ms，8 进程 73 图/秒。**模块名已冻结（numba cache 按名 pickle），不许改名导入**。
- 缓存（全部 gitignore，不进 git）：`runs/postproc_cache/val`（elevation rank，~13G）、`cache_rgb/val`（预解码 RGB npy，9.7G，index.json 带 md5 校验）、`gt_records/`（3.6G）。

### 3.3 评测口径
- **fast 档**：纯推理（FINAL only，零 GT 工作），全量 3276 图管线 ~15 分钟；E10 训练争用下 246ms/图，干净估值 ~90ms/图。
- **full 档**：+ oracle 探针 + 种子精度 + bootstrap CI（100×210 scene，~1.2h，**当前评测总时长的大头，未优化**）。
- AP 不变性已验证：fast 与 full 的 FINAL 逐字段相等（0.7254077045823377 级别的逐位一致）。

## 7. 经验清单（方法论，详细版）

### 7.1 资源纪律（两次事故换来的）
- **一切计算密集/长跑进程必须 systemd-run --user -p MemoryMax=Xg -p CPUQuota=Y% 启动**。事故：2026-08-19 eval 无上限累积 3276 图预测，RSS 248GB，两次差点/确实冻死共享机；修复=流式化（按图加载/del、RLE 化只存 KB 级、跨配置清空）+ cgroup 硬上限。
- 派发长任务前先 `ps aux | grep python` 查孤儿（被打断的派发可能已留下活进程）；agent 启动后台进程的第一件事=把 unit 名/PID 写进 STATUS 文件。
- 并行预计算 ≤16 进程；>8 worker 的基准不许无人值守；评测 OOM 时先看 cgroup MemoryCurrent vs 上限，区分匿名内存和可回收页缓存再决策。

### 7.2 内存工程
- **dict COW 页分裂**：multiprocessing fork 后每 worker 触碰大 annotation dict 会复制页，24G 标注 ×N worker 线性爆炸。根治=紧凑 GT 记录（memmap + packbits per-image items），anon 从 47.5→130G 降到 4.4G plateau。
- eval 内存三原则：按图惰性加载、张量用完即 del、只存 RLE 级中间产物；bootstrap 只重采样 RLE。

### 7.3 实验方法
- **预注册 pass 线**：跑之前把判定线和灰色区处理规则写进 RESULT.md 头部（E10 的"灰区→消融"就是预注册的），防止事后挪门柱。每阶段唯一入口 + RESULT.md + LEDGER.md。
- **oracle 探针 = 免费消融**：把管线某一环换成 GT（种子/语义/mask/评分各自做过），其余照旧，直接量出该环节值多少分。E8 用它发现种子占 +0.31 空间，E9 靠这个瞄准打赢。比全量消融便宜一个数量级。
- **零训练门控优先**：4 天否掉并重塑一个路线只烧了 35.7 分钟卡。先问"不训练能回答吗"（评分模拟、GT 天花板、解码路径、阈值 sweep 都是零训练）。
- **小参数先行**：14M 模型验证配方，成立再放大。E8 的教训：放大本身不解决头部设计问题（×20 数据指标持平），瓶颈要靠 oracle 定位后重设计（E9 种子头）。
- **数据集特性是设计的前提**：91% 接触不重叠 → 分裂不是合并；深度方差 26.4× → 全局标定；GT 1px 硬二值 → 边界收益有标注精度上限。先量数据再画架构。

### 7.4 斗兽场模式（性能优化竞赛，跑了两届，效果极好）
流程：**筹备裁判**（剖析瓶颈分步计时 → 固化输入数据包 250 图 + 参考输出 + md5 清单 → 写 PROBLEM.md 把正确性判据 C1-C5 和计时协议写死）→ **三组正交路线并行**（GPU 路线 / numba CPU 路线 / 算法缩减路线，各自 solution.py + REPORT.md + STATUS.md）→ **裁判独立复测**（不信任何自报数字，重跑正确性+串行权威计时+陌生图泛化测试）→ 冠军集成 + 全量验证。
- 判据设计要点：允许阈值内偏差（C1 计数零偏 ≥95%、C2 IoU ≥0.995、C3 probe AP |Δ|≤0.01）而非强求逐位一致，否则算法变体没法参赛；另设字节级一致组作免费回归 oracle（team_c 留用）。
- **裁判必须独立复测**：第一届 team_a 的缓存键碰撞（train/val ann_id 撞号，val 上静默盖错质心）只有裁判复测抓到，参赛方自测声明不可信。缓存键纪律：必须 (split, image_id)+内容哈希复合键，且要在缓存 miss 的陌生图上验证。
- 第二届教训：这个数据 32% 前景像素的深度梯度海拔完全相等，watershed 边界由平局规则主导——GPU 松弛复刻不了 skimage 的 FIFO age 语义（IoU 崩到 0.34-0.62），纯 GPU 路线因此输给 numba 桶队列（桶内 FIFO 精确复刻弹出序）。**换硬件之前先读懂数据的平局结构**。
- 竞赛中规则中途修改（用户解禁 GPU）→ 判决复核不重赛：按纯数字（69 vs 96ms）结论不变，修订注记进 ARENA.md。规则要留审计痕迹。

### 7.5 数值与确定性（踩过的坑，全部实测）
- **torch 标量除法走乘倒数 fast path，与 numpy 差 1 ulp**——曾让 43% 的图 RLE 改变。修法：除数用 0-dim f32 tensor 强制真 IEEE 除法。凡"预处理搬 GPU"必须过 100 图逐位门。
- **fp16 热图让 peak_local_max 把 plateau 全算成峰**（788→1503 markers），热图必须 float32。
- **CUDA 初始化后 fork 会继承 7.5G 页**：进程池要在 torch 任何 CUDA 调用之前 fork（或换 spawn）。
- **numba cache 按模块名 pickle**：模块名冻结，改名=缓存全失效。
- 确定性验证便宜且必要：同输入双跑 + 跨进程复跑，逐图 CRC32 对比。两次抓到真 bug。
- watershed 类算法的"等价"要定义清楚：桶队列+严格更小键剪枝可 99.8-100% 复刻 skimage（4/250 图 marker 平局差 1 实例，|ΔAP|=0.00012，阈值内可接受）。

### 7.6 协作流程（Claude 主线程只做派发与综合）
- 主线程永不直接执行：拆任务 → 并行派 1-3 个子智能体（各带完整上下文的任务书：路径、命令、纪律、汇报格式、字数上限）→ 综合结果。
- 长任务模式：启动 agent 挂 systemd 单元+写 STATUS → cron 每 2 小时巡检（分支逻辑：在跑/已完成自动接评测/崩溃取日志诊断不盲目重启/结果已出直接判 pass 线）→ 收尾 agent 落盘 RESULT/LEDGER+commit+push。E10 全程（训练 6.7h+评测 1.8h）无人值守跑完。
